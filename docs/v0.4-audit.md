# v0.4 — Release audit

## Scope

Release-audit van protocolversionering en historische reproduceerbaarheid volgens:

**correctheid → volledigheid → consistentie → historische integriteit → regressiecontrole**

## 1. Correctheid — PASS

- Checks slaan een concrete `protocolVersionId` en de bestaande versiesnapshot op.
- Alleen een `active` ProtocolVersion kan voor een nieuwe Check worden gebruikt.
- Een nieuwe versie start als `draft`.
- Activatie zet de vorige actieve versie op `retired`.
- Kopiëren van een versie maakt nieuwe ProtocolItems met nieuwe IDs.
- Gebruikte versies worden via `assertProtocolVersionMutable()` tegen inhoudelijke mutatie en verwijdering beschermd.

## 2. Volledigheid — PASS met één gedocumenteerde modelnuance

Milestones 4.1 t/m 4.7 zijn geïmplementeerd en getest:
- datamodel;
- migratie;
- versiebeheer;
- nieuwe/gekopieerde versies;
- Check → concrete versie;
- immutability;
- historische-integriteitstests.

De architectuur noemt dat een Protocol zonder versie kan bestaan. De huidige UI creëert bij een nieuw Protocol direct een initiële actieve versie. Dit verhindert historische reproduceerbaarheid niet en vormt geen releaseblokker, maar de implementatie ondersteunt die optionele toestand momenteel niet via de normale UI.

## 3. Consistentie — PASS

- ProtocolVersion-statussen zijn `draft`, `active` en `retired`.
- Nieuwe Checks gebruiken uitsluitend actieve versies.
- Oude Checks blijven hun opgeslagen versie gebruiken, ook nadat die versie retired is.
- `protocolVersion` blijft als backward-compatible snapshot aanwezig naast `protocolVersionId`.
- Dialogs hebben consistente, expliciete Annuleren-acties.

## 4. Historische integriteit — PASS

Bevestigd in `docs/v0.4-historical-integrity-tests.md`:
- oude Checks blijven intact;
- CheckResults blijven gekoppeld aan de oorspronkelijke ProtocolItems;
- Reviews worden niet gewijzigd door nieuwe protocolversies;
- retired versies blijven leesbaar;
- gebruikte versies en items zijn immutable;
- migratie is idempotent.

## 5. Regressiecontrole — PASS

De v0.4-wijzigingen laten de bestaande kernketens intact:
- Project → Task;
- Task → Source → SourceVersion;
- CheckResult-statusafhandeling;
- Reviewworkflow;
- bestaande backward compatibility voor oudere Checks.

De tijdens v0.4 gecorrigeerde Annuleren-knoppen zijn handmatig bevestigd.

## Bekende niet-blokkerende verbeterpunten

- Protocolkaarten inklapbaar/minimaliseerbaar maken.
- Protocolversies in de interface nieuwste-eerst tonen.
- Eventueel later expliciet ondersteunen dat een Protocol zonder ProtocolVersion bestaat.
- Verdere UX-verfijning van protocol- en bronweergave hoort niet bij de v0.4-releasecriteria.

## Releasebesluit

**GO — v0.4 is releasewaardig.**

De kernvereiste van v0.4 is gehaald: een uitgevoerde Check blijft reproduceerbaar tegen exact de ProtocolVersion en ProtocolItems die bij uitvoering golden. Latere protocolwijzigingen herschrijven de historische controleketen niet.
