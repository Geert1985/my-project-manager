# v0.2 — audit

## Doel

Deze audit controleert de eerste bron- en controleketen voordat verdere functionaliteit wordt toegevoegd.

## Gecontroleerde keten

Project -> Task -> Source -> SourceVersion -> Check -> CheckResult -> Review

## Resultaat

### Source / SourceVersion
- Een Source is een logisch bronobject.
- Een SourceVersion legt een concrete versie vast.
- Een nieuwe versie wordt toegevoegd in plaats van de bestaande versie te overschrijven.
- Een Check verwijst naar een specifieke SourceVersion.

Status: OK

### Protocol / ProtocolItem
- Protocols zijn herbruikbaar.
- ProtocolItems zijn geordend.
- Required controlepunten worden expliciet opgeslagen.
- Een Check gebruikt de ProtocolItems om CheckResults aan te maken.

Status: OK voor v0.2

Beperking: ProtocolItems zijn nog niet versioned. Inhoudelijke wijziging van een bestaand protocol moet daarom voorlopig niet worden ondersteund. Een toekomstige ProtocolVersion/ProtocolItemVersion-laag is nodig voor volledige historische reproduceerbaarheid.

### Check / CheckResult
- Een Check koppelt Task, SourceVersion en Protocol.
- Bij het starten worden CheckResults aangemaakt.
- Check-status wordt afgeleid uit de resultaten.
- Een afgeronde Check kan niet meer worden aangepast.
- Een Check bewaart de protocolversie waarmee hij werd uitgevoerd.

Status: OK

### Review
- Een Review hoort bij precies één Check.
- Alleen afgeronde Checks kunnen een Review krijgen.
- Een failed Check kan niet worden goedgekeurd.
- Een approved of rejected Review kan niet meer worden gewijzigd.

Status: OK

### Storage
De state bevat:
- projects
- tasks
- sources
- sourceVersions
- protocols
- protocolItems
- checks
- checkResults
- reviews

Bestaande localStorage-data krijgt ontbrekende arrays via normalizeState.

Status: OK

### Verwijdering en historie
Projectverwijdering verwijdert de bijbehorende taken, sources en sourceVersions.

Aandachtspunt: volledige audit-historiek vereist uiteindelijk expliciete regels voor het verwijderen of archiveren van bronnen, protocollen en controleobjecten. Dit wordt vóór een cloud/database-implementatie opnieuw ontworpen.

## Besluit

v0.2 bron- en controlelaag is functioneel voldoende stabiel voor de volgende ontwikkelfase.

De belangrijkste openstaande architectuurkwestie is protocolversionering. Die moet worden opgelost voordat we protocollen inhoudelijk kunnen bewerken zonder historische controles ongeldig te maken.

De volgende stap na deze audit is het verbeteren van de gebruikersweergave van Checks en Reviews: overzicht, duidelijke statusindicatoren en navigatie naar controlehistoriek.
