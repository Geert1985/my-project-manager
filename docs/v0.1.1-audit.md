# v0.1.1 — audit

## Resultaat

De basis van v0.1.1 is gecontroleerd op:

- projectbeheer
- task-engine
- opslag
- statusconsistentie
- projectvoortgang
- verwijdering
- invoervalidatie
- mobiele/desktopstructuur
- documentatie

## Gecontroleerd

### 1. Project-engine
- Projecten krijgen een unieke ID.
- Projecten krijgen timestamps.
- Verwijderen van een project verwijdert ook de bijbehorende taken.
- Lege projectnamen worden programmatisch geweigerd.

### 2. Task-engine
De statusmatrix in `docs/task-status-matrix.md` blijft de norm.

Extra integriteitscontrole:
- Een taak moet bij een bestaand project horen.
- Een parent-taak moet bestaan.
- Een parent en subtaak moeten tot hetzelfde project behoren.
- Lege taaknamen worden programmatisch geweigerd.
- Verwijderen van een onbekende taak veroorzaakt geen ongewenste wijziging.

### 3. Status en voortgang
- Handmatige voltooiing van een parent voltooit alle descendants.
- Automatische voltooiing ontstaat wanneer alle directe subtaken voltooid zijn.
- Nieuwe subtaken onder een voltooide parent openen de parent opnieuw.
- Ancestors worden opnieuw geëvalueerd.
- Projectvoortgang telt alleen voltooide taken.

### 4. Opslag
- State wordt via `localStorage` bewaard.
- Bestaande tasks zonder `completionMode` worden gemigreerd naar `manual`.
- Ongeldige arrays voor projecten/taken worden genormaliseerd.

### 5. UI
- HTML-output van gebruikersvelden wordt geescaped.
- De taakboom ondersteunt onbeperkte diepte.
- De mobiele navigatie en desktopweergave zijn gescheiden via responsive CSS.
- Verwijderen vereist bevestiging.

## Bewuste beperkingen van v0.1.1

De volgende zaken zijn nog geen bug, maar behoren tot volgende ontwikkelfasen:

- projecten en taken kunnen nog niet bewerkt worden
- zoeken ontbreekt
- bronnen en bronversies ontbreken
- controleprotocollen ontbreken
- geschiedenis/audit trail ontbreekt
- import/export ontbreekt
- geavanceerde foutmeldingen ontbreken
- automatische geautomatiseerde browser-tests ontbreken
- cloudopslag en gebruikers ontbreken

## Releasebesluit

**v0.1.1 is functioneel stabiel genoeg om als basisversie verder te ontwikkelen.**

De volgende grote stap wordt v0.2. Daarbij wordt eerst de bron-/controlearchitectuur ontworpen voordat nieuwe UI-complexiteit wordt toegevoegd.

Elke nieuwe wijziging aan de task-engine moet opnieuw worden getoetst aan de task-statusmatrix.
